# Laptop Price Prediction

**SAiR Regression Capstone Project**

Predicts the price of a laptop in euros from its specifications (manufacturer, type, screen, CPU, GPU,
RAM, storage, weight, operating system, product line). The project covers data cleaning, exploratory
analysis, feature extraction, model comparison with two validation protocols, hyperparameter tuning,
final evaluation, experiment tracking with MLflow, and a Streamlit app.

## Results

The final model is a tuned `GradientBoostingRegressor`, selected by cross-validated MAE on training data
only. The test set was used once, for the final evaluation.

| Estimate | MAE (EUR) | Note |
|---|---|---|
| Test set (255 laptops) | **152.7** | RMSE 232.8, R² 0.88, median error 97.3, MAPE 13.9% |
| Median-price baseline, test set | 521.4 | the final model's MAE is about 71% lower |
| Cross-validation, random folds | 157.4 ± 14.6 | laptops similar to those seen in training |
| Cross-validation, folds grouped by product | 179.5 ± 28.1 | products the model has not seen |
| Out-of-fold, grouped, training set | 176.3 | |

The test split is random, so many test laptops share a product name with training laptops. For products the
model has not seen, the grouped estimates (about EUR 180) are the better guide.

Tuned candidates (MAE in EUR, 5 folds x 3 repeats on the training set):

| Model | Random folds | Grouped by product |
|---|---|---|
| GradientBoosting (selected) | 157.4 | 179.5 |
| HistGradientBoosting | 161.1 | 182.8 |
| RandomForest | 170.6 | 194.3 |
| Ridge | 194.0 | 204.5 |

GradientBoosting and HistGradientBoosting are practically tied (grouped difference 3.3 +/- 9.9 EUR, GradientBoosting
better in 10 of 15 folds); the selection rule (lowest grouped MAE) picks GradientBoosting.

## Limitations

| Actual price | Test: n / MAE / bias | Out-of-fold: n / MAE / bias |
|---|---|---|
| below 500 | 47 / 59 / +43 | 186 / 67 / +40 |
| 500 - 1,000 | 84 / 105 / +59 | 339 / 108 / +45 |
| 1,000 - 1,500 | 64 / 161 / -8 | 250 / 172 / +58 |
| 1,500 - 2,500 | 48 / 248 / -55 | 202 / 272 / -181 |
| 2,500 and above | 12 / 428 / -341 | 43 / 767 / -584 |

(bias = mean of predicted minus actual, in EUR)

- **Estimates above about EUR 2,500 are less reliable.** The model under-predicts there, and only 43 of the 1,020
  training laptops (4.2%) and 12 test laptops fall in this range. The app warns when an estimate reaches EUR 2,500.
- Cheaper laptops (below EUR 1,000) are slightly over-priced by the model.
- Absolute error grows with price, while the relative error stays around 13-16% on the test set.
- The data are historical listings of 6th-8th generation Intel hardware. The model is a demonstration, not a
  current pricing tool.

## Dataset

Kaggle *Laptop Price Prediction*: 1,303 listings, 13 columns, target `Price_euros`. 28 rows are redundant
(14 listings that appear three times under different IDs) and are removed, leaving 1,275 laptops
(1,020 for training, 255 for testing). Place the CSV in `data/raw/` (exactly one CSV file); raw data is not
tracked by Git.

## How to run

1. **Notebook.** Open `notebook.ipynb` in JupyterLab and use *Restart Kernel and Run All Cells*. The three randomized
   hyperparameter searches take about 2-4 minutes each, so the full run takes several minutes. It writes
   `models/` (model, input options, metadata) and `experiments/` (MLflow store, figures).
2. **App.** `streamlit run app.py`. The app shows an error until step 1 has created the files in `models/`.
3. **Experiments.** `mlflow ui --backend-store-uri sqlite:///experiments/mlflow.db`, run from the project root.
   The notebook logs 23 runs: the untuned models, the tuned models under both protocols, and the final model.

## Streamlit app

Choose the laptop's specifications and press *Predict price*. The app shows the estimated price in euros, the
typical out-of-fold error for estimates in the same price range, and a warning for estimates of EUR 2,500 or more.
A product line that is not in the list can be entered as "Other (not listed)".

## Methodology

- **Leakage control.** Duplicate listings are removed before the split. Feature extraction (`LaptopFeatureExtractor`) is
  stateless; scaling and one-hot encoding are learned inside the model pipeline, on training folds only. The test set
  takes no part in any decision.
- **Validation.** Repeated 5-fold cross-validation (3 repeats, `random_state=42`) in two forms: random folds, and folds
  grouped by product, so that all rows of a product stay together. Every model sees identical folds, so differences are
  compared fold by fold. Errors are always measured in euros.
- **Features.** Parsed from the text columns: RAM, weight, four storage capacities (1 TB = 1,024 GB), touchscreen, IPS,
  resolution, CPU family, GPU family, GPU model and product line (first word of the product name).
  GPU model and product line improve both a linear and a tree model under both protocols (RandomForest MAE -17.0 and
  -20.8 EUR, Ridge -42.1 and -41.4 EUR) and are adopted. CPU detail (suffix, generation, clock) gave only 1.5-2.4% and
  did not meet the pre-defined criterion for RandomForest, so CPU family alone is kept.
- **Target.** The raw price is used: `log1p(price)` gave no gain for Ridge or RandomForest.
- **Models.** Nine models are compared; boosting and bagging models lead, linear models trail by about EUR 26-30.
  ExtraTrees is dropped because it is the most sensitive to shared product families. Tuning was optimized on grouped MAE;
  it helps HistGradientBoosting clearly and GradientBoosting modestly. A refinement round gave no meaningful gain
  and was not adopted.
- **Final model.** Configuration selected by the search: `loss='huber'`, `n_estimators=537`, `learning_rate=0.1449`,
  `max_depth=2`, `min_samples_leaf=2`, `subsample=0.977`, `max_features=0.615`. The saved model is refit on all
  1,275 laptops; the test figures above describe the same configuration trained without the test set.

## Reproducibility

- Randomness is controlled by passing `random_state=42` explicitly everywhere; no global seed is set.
- `models/model_metadata.json` records the Python, scikit-learn, pandas and numpy versions used to train the saved model.
- The saved model refers to `utils.LaptopFeatureExtractor` by name. Keep `utils.py` importable next to `app.py`, and
  re-run the notebook if that class is renamed or moved.
- A model file saved with one scikit-learn version may not load under another; re-run the notebook after changing versions.
